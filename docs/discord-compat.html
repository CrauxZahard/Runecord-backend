Reference

Discord-compatible API.

The same Runecord server exposes a Discord-shaped surface at /api/v1. String IDs, nested authors, ISO timestamps and Discord error codes, so existing libraries and habits have less to relearn.

This is a compatibility layer, not Discord

Requests still hit your local server and enforce Runecord permissions. Nothing is forwarded to Discord. The subset is intentionally smaller than the native API.

Base path and auth

Mounted alongside the native routes, the compatibility API lives under /api/v1. Authentication is unchanged: Bot for bot tokens and Bearer for human sessions.

GET http://127.0.0.1:47800/api/v1/users/@me
Authorization: Bot rcbot.5d41402abc4b…

Payload shapes

IDs are strings, timestamps are ISO-8601, authors are nested inside messages, and reactions use an emoji object. Fields that are absent on a message in the native API may be filled with Discord defaults such as type: 0.

json 
{
  "id": "9081",
  "channel_id": "12",
  "author": {
    "id": "7",
    "username": "maya",
    "global_name": "Maya Chen"
  },
  "content": "shipped it.",
  "timestamp": "2026-11-14T12:00:00.123Z",
  "type": 0,
  "reactions": [
    { "emoji": { "id": null, "name": "🔥" }, "count": 3, "me": false }
  ]
}

Compare the native message: integer IDs, a flat author reference and Unix milliseconds. Both endpoints read and write the same rows.

{ "id": 9081, "channel_id": 12, "author": { "id": 7 }, "timestamp": 1794691200123 }

Error codes

Errors use the Discord envelope and a small set of Discord codes. The HTTP status still carries the category.

CodeMessageMeaning
10003Unknown ChannelThe channel does not exist or is not visible
10008Unknown MessageThe message does not exist or was deleted
50001Missing AccessThe token cannot see this resource
50035Invalid Form BodyA required field is missing or malformed
 
{ "code": 50001, "message": "Missing Access" }

Gateway

The HTTP surface has a matching gateway at /gateway/v1. It speaks the Discord handshake: HELLO, IDENTIFY, HEARTBEAT, RESUME, and DISPATCH frames with sequence numbers.

GET ws://127.0.0.1:47800/gateway/v1
# send IDENTIFY after HELLO
{ "op": 2, "d": { "token": "Bot rcbot.…", "intents": 37379 } }

See Gateway for the opcode table, intents, heartbeat interval and resume buffer.

Differences and limitations

  • The compatibility surface covers users, guilds, channels, messages, reactions, pins, typing and the gateway. It is not every native route.
  • DM create/update/remove events are not dispatched on the v1 gateway; use the native gateway for the full event set.
  • Message content in guild channels requires the MESSAGE_CONTENT intent. Direct messages are exempt.
  • Voice uses Runecord's native signalling; there is no Discord voice transport.
  • Snowflakes are stringified integers, not real Discord snowflakes. Do not parse timestamps out of them.

Using existing tooling

  1. Point the REST base URL at http://127.0.0.1:47800/api/v1.
  2. Use a Runecord bot token with the Bot scheme.
  3. Request the intents you need; omit them to receive everything.
  4. Expect Runecord permissions and rate-limit buckets, not Discord's exact limits.
  5. Fall back to the native API for applications, audit logs, events, group DMs and voice.
Good fit for bridges and dashboards

If an existing library only needs messages, channels and guilds, the compatibility layer usually works unchanged. If it depends on Discord-only features, keep it on the native API.
