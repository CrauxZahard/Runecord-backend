The same API that powers the Runecord client is available to your bots, tools and integrations. No separate developer server, no mock data.

HTTP API

Guilds, channels, messages, roles, members and uploads. Session tokens for people, bot tokens for automation.

Quick start

Three calls to a live bot.

Three calls and one WebSocket. The server ships with a demo seed for local testing, so there is data to play with immediately.

01

Run the server

Start the Rust backend on loopback. It creates and encrypts the database on first launch.

runecord-server --data data
02

Create a bot

Log in as a human, then create a bot. The returned token is shown exactly once.

POST /api/bots
03

Connect

Send Authorization: Bot rcbot.… to the HTTP API or open the gateway for events.

GET /gateway
Demo accounts are available locally

Fresh databases seed nova, maya, leo, sam, ana, priya and tom with the password runecord. Pass --no-demo for a public deployment.

Compatibility

Native JSON. Discord shapes.

Use the native API when you want compact payloads and integer IDs. Use /api/v1 when you want Discord-shaped objects, string snowflakes and existing libraries to feel at home.

  • Same server, same auth, same permissions
  • String IDs and ISO timestamps on /api/v1
  • Discord error codes such as 50001 Missing Access
  • Discord-style gateway at /gateway/v1

Under the hood

Same server. Same permissions.

The developer surface is the production surface. Every route enforces permissions, rate limits and the same storage rules as the client.

Encrypted at rest

The database and CDN uploads are sealed with AES-256-GCM. Tokens are stored as SHA-256 hashes, not plaintext.

Permissions everywhere

Base permissions, channel overwrites, role hierarchy, timeouts and audit logs apply to bots exactly as they do to people.

Local by default

SQLite in memory, encrypted flushes, zero external caches. Self-host on one box or put a TLS proxy in front of it.
