Quick start

Make your first API call.

Run the backend locally, authenticate, create a bot and connect to the gateway. This guide assumes the Runecord client and backend repositories are siblings on your machine.

Base URL

http://127.0.0.1:47800 by default. Change it with --port, or put a TLS reverse proxy in front for remote clients.

1. Run the server

From Runecord-backend, start the Rust service. The first launch creates the encrypted database, applies the migrations and seeds the demo accounts.

bash 
cargo run --release -p runecord-server -- --data data

The server defaults to 127.0.0.1:47800. For a public deployment, bind every interface and skip the demo seed:

bash 
runecord-server --host 0.0.0.0 --port 47800 --data data --no-demo
Terminate TLS in front of the server

The reverse proxy must forward ordinary HTTP and the WebSocket upgrade for /gateway, /gateway/v1 and /voice on the same host and port. The client derives ws:// or wss:// from the URL you configure.

2. Authenticate

Register a new account, or log in to a seeded demo account. Both return a session token and the user object.

bash
curl -s -X POST http://127.0.0.1:47800/api/login \
  -H "Content-Type: application/json" \
  -d '{"username":"nova","password":"runecord"}'
js
const response = await fetch("http://127.0.0.1:47800/api/login", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ username: "nova", password: "runecord" }),
});

const { token, user } = await response.json();
python
import requests

response = requests.post(
    "http://127.0.0.1:47800/api/login",
    json={"username": "nova", "password": "runecord"},
)
token = response.json()["token"]

Send the token as a bearer header on every human-session request:

Authorization: Bearer <session-token>
EndpointAuthPurpose
POST /api/registerPublicCreate a local account
POST /api/loginPublicExchange credentials for a token
POST /api/logoutSessionRevoke the current token
GET /api/bootstrapSessionLoad the full client state
Demo accounts

A fresh database includes nova, maya, leo, sam, ana, priya and tom. The password for all of them is runecord.

3. Create a bot

Human sessions manage bots. Create one with the session token; the response includes a bot token that is shown once.

bash 
curl -s -X POST http://127.0.0.1:47800/api/bots \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Runebot","guild_id":1}'
{
  "bot": { "id": 42, "username": "runebot", "is_bot": true },
  "token": "rcbot.5d41402abc4b…"
}

Bot tokens use the Bot scheme, not Bearer:

Authorization: Bot rcbot.5d41402abc4b…

Passing guild_id adds the bot as a guild member and requires MANAGE_GUILD. Without it, the bot exists but is not in any server yet.

The token is shown once

Tokens are stored as SHA-256 hashes. If you lose it, delete the bot and create another, or rotate the token through an application.

4. Read the bootstrap

GET /api/bootstrap returns the signed-in user, guilds, DMs, channels and read state in one payload. Use it to discover the channel ID for the next step.

bash
curl -s http://127.0.0.1:47800/api/bootstrap \
  -H "Authorization: Bearer $TOKEN"

Native IDs are 64-bit integers and appear as JSON numbers. The Discord-compatible surface returns the same data with string IDs and ISO timestamps.

5. Send a message

Post into a channel with the bot token. The bot needs VIEW_CHANNEL and SEND_MESSAGES, and it must be a member of the guild.

bash
curl -s -X POST http://127.0.0.1:47800/api/channels/12/messages \
  -H "Authorization: Bot $BOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"content":"Hello from the API","nonce":"demo-1"}'

Every connected client receives the message over the gateway as a message_create event.

6. Listen for events

The native gateway is a WebSocket at /gateway. Authenticate with the same Bot header and read newline-free JSON frames with an { op, d } envelope.

js
import WebSocket from "ws";

const ws = new WebSocket("ws://127.0.0.1:47800/gateway", {
  headers: { Authorization: `Bot ${process.env.BOT_TOKEN}` },
});

ws.on("message", (raw) => {
  const event = JSON.parse(raw);
  if (event.op === "message_create") {
    console.log(event.d.author.username, event.d.content);
  }
});

The first frame is ready with the full bootstrap. Send {"op":"subscribe","d":{"channel_id":12}} to narrow a connection to one channel, and {"op":"heartbeat"} to keep it alive.

Browser WebSockets cannot set headers

Use a server-side client for the native gateway, or connect to /gateway/v1 and send the token in an IDENTIFY frame.
